> 文档状态：第二部分（图形与文档模型）已实现，等待用户审阅。第一部分已获用户同意继续；以下仍区分领域模型能力与 CLI 功能，不能视为最终验收声明。

## 一、架构方案

### 1. 目标与阶段边界

使用 TypeScript、面向对象和 Command 模式实现 CLI SVG 编辑器。最终包含作业要求的全部文档、编辑、显示及历史命令，内置 rect / circle / ellipse / line / text / g 六种图形。不实现后续阶段的 box 或动态插件加载。

遵守字段封装、一类一文件、文件名与类名一致；共享行为使用类层次与多态，不使用公共数据袋和散落的按图形标签分支。

### 3. 设计模式选择及落地计划

**Command（必选）**：命令对象封装一次操作，CLI 只分发，不直接修改模型。第一部分已有 Command 接口及 HelpCommand。第三部分加入 MoveCommand、GroupCommand 等编辑命令及历史执行契约；当前接口不代表撤销机制已经实现。

**Composite（第二部分已实现）**：抽象 Shape 提供统一操作；GeometryShape 负责几何字段的校验与变换，五种叶子配置自己的字段与位置/尺寸规则；Group 提供子树。Shape 的变换遍历对所有节点进行多态预计算，通过后才统一应用。文档根是结构容器，不作为可供用户删除或分组的普通图形。

**Memento**：历史管理器保存编辑前后的独立模型快照。恢复同时恢复层级、顺序、属性和 id 索引。失败不入栈；undo 后成功新编辑清空 redo。单次快照时间和空间为 O(N)，第一阶段优先选择可验证的正确性；后续可替换为差量记录。第三部分实现。

**Factory（第二部分已实现命令参数创建）**：ShapeFactory 通过一处 Map 选择具体类，各类自行解析自己的参数并处理几何和属性规则，调用方不按标签名重复判断。SVG 元素读入将在第五部分复用此工厂边界，目前尚未实现。

按名字分派仅允许两个集中位置，均标记为后续阶段待重构边界：

1. 命令分发：当前 `cli/CommandRegistry.ts` 中命令名到实现的 Map；后续将固定启动注册扩展为命令提供者注册。
2. 图形工厂：已实现的 `domain/ShapeFactory.ts`，类型名到类；后续支持 ShapeProvider 注册，但本阶段不建立完整插件系统。

属性名白名单是各图形的属性校验规则，不用于判断并分发图形类型。SVG 输出通过多态生成结构化元素表示，XML 适配器统一转义和编码，避免新增一套标签分支。

### 4. 依赖方向规则

| 模块 | 允许依赖 | 理由 |
| --- | --- | --- |
| domain | domain 内部及语言标准能力 | 保持图形行为与交互、存储无关 |
| application | application、domain | 表达用例，使用自己定义的端口接口 |
| cli | cli、application、Node 终端 API | 接收输入并调用命令，不修改领域结构 |
| presentation | presentation、domain、application 的输出端口 | 读取模型，负责文本格式，实现查询输出接口 |
| infrastructure | infrastructure、application 的端口、domain、Node 文件 API、XML 库 | 实现接口，把外部数据转换为模型 |
| main | 各模块公开入口 | 组合根，选择并注入具体实现 |

应用层若需要 tree/show 输出，通过 application/ports 中的查询输出接口接收适配器，避免 application 反向导入 presentation。presentation 可以实现该端口，增加的依赖仅指向 application 的接口。

禁止 domain 导入 application/cli/infrastructure/presentation，禁止 application 导入具体文件或 XML 实现，禁止 cli 越过应用层修改图形。发现违反规则的依赖时记入待处理项并修复。

### 6. 关键语义与待确认细节

以下为审核方案沿用的实现约定。第二部分已实现其中的模型规则；命令会话、文件读写及历史规则仍待后续：

- id 全局唯一、大小写敏感。读入时先收集显式 id，再生成不冲突的“标签名+序号”；成功加载后打印补 id 警告。
- 编辑失败不改变文档、历史、保存路径等状态。读入先构造候选文档，通过校验后整体替换。
- move 对容器递归修改后代几何坐标；scale 按原点同乘位置和尺寸，不额外修改 stroke-width 或字体大小。
- set g 的公共属性设置容器本身，遵循 SVG 继承，不覆盖子元素显式样式。
- group/addto 检查自包含、祖先后代冲突、重复参数和循环；叶子与容器统一寻址。
- 跨父容器 group：新组放在最近公共容器中，子节点按原文档顺序排列；插入到最早受影响的直接子分支之前。其他原父容器保留，即便变为空容器。实现前用具体样例验证规则。
- ungroup 按作业明确规定拒绝解散根级容器；合法解散时孩子占据原组位置。
- front 将节点移至同级列表末尾，back 移至开头，符合 SVG 绘制顺序。
- 成功的 init/read/save/canvas 尺寸修改清空历史并设屏障；undo/redo 输出指定禁用错误，直到下一次成功编辑开始新的历史。失败操作和查询不改变历史。
- save 指定新路径成功后更新当前保存路径。无参数且没有路径时给出用法错误。
- 只保证六种元素及规定属性的读写。未知且会影响结果的结构、属性或变换明确报错，不静默丢弃；完整 transform/CSS 等支持不纳入默认范围。最终支持子集须在第五部分落实并列明。
- # 只有在一行的首个非空白字符位置才表示注释，颜色 #4a90d9 是普通参数。双引号参数由后续独立分词器处理。

### 7. 第二部分模型实现说明

| 类/接口 | 已落地的职责 |
| --- | --- |
| Shape | 只读 id、公共样式、统一 move/scale/set、子树遍历、输出 DTO 与多态深复制 |
| GeometryShape | 封装数值字段；分别记录水平位置、垂直位置与非负尺寸；先验证再替换字段 |
| Rect/Circle/Ellipse/Line/Text | 各自参数、几何白名单、输出标签和具体类型深复制；Text 另外管理文本内容 |
| Group | 组合子树；子列表不提供原地增删接口，结构替换生成新组；样式不覆盖子节点 |
| ShapeFactory/ShapeArguments | 唯一图形名字分派位置及各类型参数个数、数值读取 |
| SvgDocument | 画布、根节点、id/父级索引、模型编辑、结构变更及深复制 |
| NumericValue/DomainError | 有限十进制数、非负尺寸/线宽、正画布/缩放系数及可预期领域错误 |
| SvgElement | 独立输出 DTO，供后续 XML 编码使用；不能替代有行为的图形模型 |

**字段与结构的所有权**：id 没有 setter。Group 构造及文档接收图形时会复制子树，防止调用方保留的引用影响文档。roots/children 返回数组副本，attributes 返回冻结的属性副本。结构修改通过 SvgDocument 完成：先构造候选树，验证并重建两个索引，再整体提交；失败不替换当前状态。

**按 id 重新查询**：结构修改会替换图形实例，先前查询到的 Shape 引用不保证继续指向当前文档节点。应用层应保存 id，每次执行或查询时通过文档获取当前对象，这与作业的 id 寻址规则一致。几何和属性操作不改变 id 或父子结构。

**几何原子性**：移动/缩放先遍历整棵目标子树并计算所有新值；如果某个后代发生数值溢出，之前的后代也不会被修改。通过后仅执行字段替换。位置允许有限负数和小数；形状尺寸与半径允许 0；画布尺寸及缩放系数必须大于 0。数字拒绝 NaN、Infinity、带 px 单位或十六进制形式。

**结构语义**：group 至少接收两个不同节点，按文档顺序排列，祖先与后代不可同时选择。跨父级规则已经使用具体测试落实：scene 下 node1(r,t)、node2(c,e)、edge，执行 group bundle e t r 后，scene 下顺序为 bundle(r,t,e)、空 node1、node2(c)、edge。根级组仍禁止 ungroup；内层组解散时孩子占据原位置。解组不向孩子复制组样式，这是结构解散而不是样式烘焙。

**复杂度取舍**：完整深复制和索引重建为 O(N)，快照不共享可变状态。结构重建暂以易验证为目标，嵌套替换可能重复复制祖先子树，最坏约 O(N×H)，H 为树高；后续确有大文档需求时再优化，不提前引入共享可变树和索引同步机制。

**阶段边界**：SvgDocument 的模型方法已经涵盖 insert/delete/move/scale/setAttribute/group/ungroup/addTo/front/back；它们还不是可输入的 CLI 命令。第三部分用 Command 封装这些行为，并加入会话、历史与撤销屏障。toSvgElement 只是结构化表示，当前不会读写 SVG 文件。
