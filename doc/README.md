# PJ1 Phase 1：SVG CLI 编辑器项目文档

> 文档状态：第四部分（tree/show、帮助与查询隔离）已实现，等待用户审阅。前三部分已获用户同意继续。SVG 文件读写尚待第五部分，不能视为最终验收声明。

## 一、架构方案

### 1. 目标与阶段边界

使用 TypeScript、面向对象和 Command 模式实现 CLI SVG 编辑器。最终包含作业要求的全部文档、编辑、显示及历史命令，内置 rect / circle / ellipse / line / text / g 六种图形。不实现后续阶段的 box 或动态插件加载。

遵守字段封装、一类一文件、文件名与类名一致；共享行为使用类层次与多态，不使用公共数据袋和散落的按图形标签分支。

### 3. 设计模式选择及落地计划

**Command（第三部分已实现）**：每次输入创建一个命令对象。十条编辑命令继承 EditCommand，具体 edit 方法只操作传入的候选文档。HistoryManager 作为调用者记录完成的命令，撤销/重做调用命令的 undo/redo，命令内部保存私有快照。CLI 不修改图形模型。init/canvas/help/undo/redo 使用普通 Command，不混入编辑历史。

**Composite（第二部分已实现）**：抽象 Shape 提供统一操作；GeometryShape 负责几何字段的校验与变换，五种叶子配置自己的字段与位置/尺寸规则；Group 提供子树。Shape 的变换遍历对所有节点进行多态预计算，通过后才统一应用。文档根是结构容器，不作为可供用户删除或分组的普通图形。

**Memento（第三部分已实现）**：每个 EditCommand 保存编辑前后的独立模型快照，快照不直接暴露。undo/redo 返回新的深复制文档，包含层级、顺序、属性和重建的 id 索引。失败不入栈；undo 后成功新编辑清空 redo。单个文档快照时间和空间为 O(N)，K 条历史约 O(KN)，大文档优化留到有实际需求时。

**Factory（第二部分已实现命令参数创建）**：ShapeFactory 通过一处 Map 选择具体类，各类自行解析自己的参数并处理几何和属性规则，调用方不按标签名重复判断。SVG 元素读入将在第五部分复用此工厂边界，目前尚未实现。

**Visitor（第四部分新增）**：Shape 接受泛型 ShapeVisitor，六种具体类分别调用自己的 visit 方法；ShapeFormatter 在 presentation 实现接口，按多态入口生成类型特有的几何摘要。domain 不包含 CLI 排版或树字符，显示层也无需 switch(tag) 或类型名映射。该访问者针对当前固定六种类型，新独立类型需补充访问者方法；未来动态插件阶段再评估显示提供者接口。

按名字分派仅允许两个集中位置，均标记为后续阶段待重构边界：

1. 命令分发：当前 `cli/CommandRegistry.ts` 中命令名到实现的 Map；后续将固定启动注册扩展为命令提供者注册。
2. 图形工厂：已实现的 `domain/ShapeFactory.ts`，类型名到类；后续支持 ShapeProvider 注册，但本阶段不建立完整插件系统。

属性名白名单是各图形的属性校验规则，不用于判断并分发图形类型。SVG 输出通过多态生成结构化元素表示，XML 适配器统一转义和编码，避免新增一套标签分支。

### 4. 依赖方向规则

| 模块 | 允许依赖 | 理由 |
| --- | --- | --- |
| domain | domain 内部及语言标准能力 | 保持图形行为与交互、存储无关 |
| application | application、domain | 表达用例，使用自己定义的端口接口 |
| cli | cli、application、Node 终端 API | 接收输入并调用命令，不修改领域结构 |
| presentation | presentation、domain、application 的输出端口 | 读取模型，负责文本格式，实现查询输出接口 |
| infrastructure | infrastructure、application 的端口、domain、Node 文件 API、XML 库 | 实现接口，把外部数据转换为模型 |
| main/EditorApplication | 各模块公开入口 | 组合根，选择并注入具体实现；测试和 CLI 共享装配 |

tree/show 已通过 application/ports/DocumentPresenter 接收适配器，application 不反向导入 presentation。TextDocumentPresenter 实现该端口；组合根创建并注入它。领域层的 ShapeVisitor 仅引用领域类型，编译后没有对具体显示层的依赖。

禁止 domain 导入 application/cli/infrastructure/presentation，禁止 application 导入具体文件或 XML 实现，禁止 cli 越过应用层修改图形。发现违反规则的依赖时记入待处理项并修复。

### 6. 关键语义与待确认细节

以下为审核方案沿用的实现约定。第三部分已落实模型、命令会话及 init/canvas 历史规则；read/save 相关规则待第五部分：

- id 全局唯一、大小写敏感。读入时先收集显式 id，再生成不冲突的“标签名+序号”；成功加载后打印补 id 警告。
- 编辑失败不改变文档、历史、保存路径等状态。读入先构造候选文档，通过校验后整体替换。
- move 对容器递归修改后代几何坐标；scale 按原点同乘位置和尺寸，不额外修改 stroke-width 或字体大小。
- set g 的公共属性设置容器本身，遵循 SVG 继承，不覆盖子元素显式样式。
- group/addto 检查自包含、祖先后代冲突、重复参数和循环；叶子与容器统一寻址。
- 跨父容器 group：新组放在最近公共容器中，子节点按原文档顺序排列；插入到最早受影响的直接子分支之前。其他原父容器保留，即便变为空容器。实现前用具体样例验证规则。
- ungroup 按作业明确规定拒绝解散根级容器；合法解散时孩子占据原组位置。
- front 将节点移至同级列表末尾，back 移至开头，符合 SVG 绘制顺序。
- 成功的 init/read/save/canvas 尺寸修改清空历史并设屏障；undo/redo 输出指定禁用错误，直到下一次成功编辑开始新的历史。失败操作和查询不改变历史。
- save 指定新路径成功后更新当前保存路径。无参数且没有路径时给出用法错误。
- 只保证六种元素及规定属性的读写。未知且会影响结果的结构、属性或变换明确报错，不静默丢弃；完整 transform/CSS 等支持不纳入默认范围。最终支持子集须在第五部分落实并列明。
- # 只有在一行的首个非空白字符位置才表示注释，颜色 #4a90d9 是普通参数。双引号参数由后续独立分词器处理。

### 7. 第二部分模型实现说明

| 类/接口 | 已落地的职责 |
| --- | --- |
| Shape | 只读 id、公共样式、统一 move/scale/set、子树遍历、输出 DTO 与多态深复制 |
| GeometryShape | 封装数值字段；分别记录水平位置、垂直位置与非负尺寸；先验证再替换字段 |
| Rect/Circle/Ellipse/Line/Text | 各自参数、几何白名单、输出标签和具体类型深复制；Text 另外管理文本内容 |
| Group | 组合子树；子列表不提供原地增删接口，结构替换生成新组；样式不覆盖子节点 |
| ShapeFactory/ShapeArguments | 唯一图形名字分派位置及各类型参数个数、数值读取 |
| SvgDocument | 画布、根节点、id/父级索引、模型编辑、结构变更及深复制 |
| NumericValue/DomainError | 有限十进制数、非负尺寸/线宽、正画布/缩放系数及可预期领域错误 |
| SvgElement | 独立输出 DTO，供后续 XML 编码使用；不能替代有行为的图形模型 |

**字段与结构的所有权**：id 没有 setter。Group 构造及文档接收图形时会复制子树，防止调用方保留的引用影响文档。roots/children 返回数组副本，attributes 返回冻结的属性副本。结构修改通过 SvgDocument 完成：先构造候选树，验证并重建两个索引，再整体提交；失败不替换当前状态。

**按 id 重新查询**：结构修改会替换图形实例，先前查询到的 Shape 引用不保证继续指向当前文档节点。应用层应保存 id，每次执行或查询时通过文档获取当前对象，这与作业的 id 寻址规则一致。几何和属性操作不改变 id 或父子结构。

**几何原子性**：移动/缩放先遍历整棵目标子树并计算所有新值；如果某个后代发生数值溢出，之前的后代也不会被修改。通过后仅执行字段替换。位置允许有限负数和小数；形状尺寸与半径允许 0；画布尺寸及缩放系数必须大于 0。数字拒绝 NaN、Infinity、带 px 单位或十六进制形式。

**结构语义**：group 至少接收两个不同节点，按文档顺序排列，祖先与后代不可同时选择。跨父级规则已经使用具体测试落实：scene 下 node1(r,t)、node2(c,e)、edge，执行 group bundle e t r 后，scene 下顺序为 bundle(r,t,e)、空 node1、node2(c)、edge。根级组仍禁止 ungroup；内层组解散时孩子占据原位置。解组不向孩子复制组样式，这是结构解散而不是样式烘焙。

**复杂度取舍**：完整深复制和索引重建为 O(N)，快照不共享可变状态。结构重建暂以易验证为目标，嵌套替换可能重复复制祖先子树，最坏约 O(N×H)，H 为树高；后续确有大文档需求时再优化，不提前引入共享可变树和索引同步机制。

**阶段演进**：上述模型方法在第二部分先独立实现，第三部分现已用 Command 接入 CLI，并加入会话、历史与撤销屏障。toSvgElement 仍只是结构化表示，当前不会读写 SVG 文件。

### 8. 第三部分命令与历史实现说明

编辑执行路径：`main → EditorApplication → Repl/CommandRegistry → Tokenizer → CommandExecutor → 具体 EditCommand → HistoryManager → SvgDocument`。EditorApplication 是组合根，不是新增业务层；第三部分注册十五条命令，第四部分补充查询后共十七条。每次分发创建新命令实例，避免后一次执行覆盖前一次命令的撤销快照。

编辑命令的统一生命周期：

1. 确认已有当前文档，创建原状态快照和独立候选文档。
2. 参数验证和具体编辑只在候选文档上执行；失败则丢弃候选，不改会话、路径、undo、redo 或屏障。
3. 成功后命令保存前后快照，会话接收其副本，再入 undo 栈、清空 redo、解除屏障。
4. undo/redo 从栈顶命令取得快照副本，成功替换会话文档后才移动栈项。redo 恢复快照而不重新解析或执行用户输入。

HistoryManager 统一管理两栈和屏障；EditorSession 管理当前文档和保存路径。普通编辑不能修改路径，init 成功会清空路径。为第五部分预留 openDocument/markSaved/resetAfterIo 的成功后调用点；本次只在测试中模拟保存成功后的钩子，不声称已有 SVG 文件保存功能。

**历史边界**：成功 init/canvas 尺寸修改清空旧历史并设屏障，undo 和 redo 都返回作业指定的 `undo not allowed after io command`。失败编辑不能解禁。下一次成功编辑形成新的历史；撤销完新历史只会到达当前文档边界。help、canvas 无参查询、空行和注释都不改历史。移动 0 或对已在最前的节点执行 front 也是成功编辑，仍按一条命令一个单元记录。

**参数与显示**：init 接受 0/1/2 个参数，缺省宽高分别取 800/600；canvas 查询不带参数，修改必须同时给出宽高。create 的尾部 in 指定父容器，text 的内容仍为单一参数，允许空文本及字面量 in。编辑结果为一行操作摘要；undo 使用 `undone:` 标明撤销的原操作，redo 回显原摘要。第四部分现已补齐 tree/show 的属性明细。

**分词提前实现**：为保证第三部分 create/set 文本可用，将原定第四部分的双引号分词提前。支持空参数、带空格内容、双引号内的反斜杠/引号转义；其他反斜杠保留，颜色 # 不被当成行内注释。未闭合引号直接报错，命令不会开始执行。此变更已记入过程记录。

**错误边界**：领域错误由 application/CommandExecutor 转为 CommandError，CLI 只依赖应用层。REPL 为预期错误加统一 error: 前缀并继续读取，同时清除错误消息中的换行，保持一行一错。程序错误继续抛出，便于发现实现缺陷。

**工程归档**：所有运行所需源码、测试、示例、文档、配置、依赖锁文件均在单一 svg-editor 文件夹。work 中仅有开发缓存，不作为运行依赖。最终打包在第六部分整理，生成内容不包含 node_modules/dist 等可重建文件；本次仅本地提交，不配置远程，不打 final 标签。

### 9. 第四部分查询与显示实现说明

查询执行路径：`TreeCommand/ShowCommand → DocumentPresenter 接口 → TextDocumentPresenter → ShapeFormatter/ShapeVisitor`。命令先确认文档存在、参数个数及目标 id，再把当前文档的深复制交给显示适配器；它们实现普通 Command，没有 HistoryManager 依赖，不创建历史项。

| 能力 | 具体输出规则 |
| --- | --- |
| tree | 首行为 svg (宽x高)，按子节点绘制顺序递归；使用 ├──、└──、│ 和缩进表示层级 |
| tree id | 以指定图形为首行，不保留原树的前导缩进；叶子仅一行，空组仅显示自身 |
| 图形摘要 | rect 显示 x/y/w/h；circle 显示 cx/cy/r；ellipse 显示 cx/cy/rx/ry；line 显示端点箭头；text 显示坐标及引用文本 |
| show id | 首行为类型、id 和直接父级；根级图形为 parent=svg，嵌套图形为 parent=g#id；随后列出完整几何字段名、文本和显式样式 |
| 容器信息 | show 额外列出直接 children 数量，空组为 0；tree 内联组自身的显式样式 |
| 样式与文本 | 样式按 fill、stroke、stroke-width 的稳定顺序显示；不计算继承值，不补写省略的默认样式；空文本显示双引号空串 |

树中图形标签与字段使用单个空格分隔，不依赖不同终端对中文 id 的字符宽度估计。show 使用两空格缩进。文本和包含空白的样式值使用 JSON 风格引用，换行、引号、反斜杠及 Unicode 行分隔符均转义，保持树的一行对应一个图形。

ShapeFormatter 的摘要由访问者多态实现，明细从封装模型的属性副本读取；类型名仅用于显示标签，不参与新增条件分派。DocumentPresenter 接口使应用层只依赖抽象；显示适配器仅返回字符串，不直接访问终端。

查询快照提供额外隔离：即使格式化器误改输入文档或随后抛出领域错误，真实会话、路径和 redo 仍保持不变。总查询成本包含 O(N) 的文档深复制；对子树也复制全文档，以简单、可验证的隔离为优先，未来大文档再考虑只读模型视图。

help 已补齐十七条可用命令、六种 create 参数、set 白名单、分词/默认值/变换/分组/查询/历史规则；read/save 语法列入第五部分计划区域，避免把尚未实现的能力显示为可用。
